# REVIEW.md

Findings on the starter `app/main.py`. Every "how you'd notice it" below was reproduced by running the starter
(Python 3.12, server clock in UTC), not guessed.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` + `datetime.now()` / `datetime.fromtimestamp()` in `punch_in`, `create_employee` | PyMongo returns **naive** datetimes and the code uses the **server's local time zone** for everything. Instants have no defined zone. | Punch in at 01:00 IST on 7 Jul (= 19:30 UTC on 6 Jul): stored `punch_in` is `2026-07-06T19:30:00` with no zone. | `tz_aware=True` on the client, UTC-aware datetimes everywhere, conversion to/from epoch ms in one place (`dt_to_ms`, `to_dt`). |
| 2 | `compute_late_minutes` | (a) `int(total_seconds()/60)` floors **before** the `> 10` test, so 10:00-10:59 of lateness is never late. (b) `replace(hour=...)` uses the punch-in's own (UTC/naive) date and zone against an **IST** shift string. (c) No overnight handling. (d) Seconds are not truncated. | Shift 09:30, punch-in 09:40:30 returns **0**; the contract says 10 (09:40:01 -> 10). | Work in whole epoch seconds: `delta = punch_in - shift_start(attendance date, IST)`; late iff `delta > 600`, then `delta // 60`. |
| 3 | `compute_work_hours` | `round(x, 2)` is not half-up (it rounds the binary float, ties go to even). Seconds not truncated. | 450 s = 0.125 h returns **0.12** (should be 0.13); 9630 s = 2.675 h returns **2.67** (should be 2.68). | Integer arithmetic: `(2*secs + 36) // 72` hundredths, so there is no float rounding at all. |
| 4 | `compute_overtime` | (a) No 30-minute threshold. (b) The shift end is always on the record's date, so an overnight shift's end is a day early. (c) Mixes naive and aware datetimes. | Punch-out 18:40 on a 18:30 shift returns **10** (should be 0). Overnight 22:00-06:00, out 06:40 next day returns **1480** (should be 40). A naive `punch_out` raises `TypeError`. | `shift_instant(date, shift_end, +1 day if overnight)`, floor to minutes, return it only when >= 30. |
| 5 | `EmployeeIn` | No validation at all. | `emp_code="x"`, `name=""`, `email="nope"`, `joined_on="not-a-date"`, `shift_start="99:99"` returns **201**. `shift_start == shift_end` also accepted. | Pydantic constraints from the OpenAPI schema (patterns, lengths, real calendar date, shifts must differ). |
| 6 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) with no unique index: two concurrent creates both succeed. `created_at` is naive local time returned as an ISO string, not epoch ms. | Parallel POSTs of the same `emp_code` produce duplicates. Response shows `"created_at": "2026-10-11T19:22:01.597746"`. | Unique index on `emp_code`; `DuplicateKeyError` becomes 409. `created_at` is a UTC datetime, returned as epoch ms. |
| 7 | `list_employees` | `skip = page * page_size` skips the first page. `total` is `count_documents({})` (ignores the filter). No sort. `page`/`page_size` unchecked (no max of 100). `if department:` ignores `""`. | `page=1&page_size=3` starts at EMP0004. `department=A` (5 employees) reports `total: 25`. `page_size=100000` returns 200. | `skip=(page-1)*page_size`, `count_documents(filter)`, `sort emp_code`, `Query(ge=1, le=100)`, `department is not None`. |
| 8 | `punch_in`, `emp = find_one(...)` | Unknown employee is never checked; `emp["shift_start"]` raises `TypeError`. | `POST /attendance/punch-in {"emp_code":"NOPE"}` returns **500**. | `emp_or_404` -> 404. |
| 9 | `PunchInIn.status` | Plain `str`: any value accepted, including `ABSENT`, which must not be created by punch-in. | `{"status":"ABSENT"}` returns **201**. | `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 10 | `PunchInIn.punched_at` / `punch_in` | Not validated (seconds, floats, huge numbers accepted), `if body.punched_at` is a truthiness test, and milliseconds are kept in the stored instant. | `punched_at: 1783312500` (seconds) returns **201** and is dated 1970. A punch at `...:00.900` is stored as `04:00:00.900000` (R1 wants whole seconds). | Strict int in `[1e11, 4.1e12]` (422 otherwise); explicit `is None`; truncate to whole seconds. |
| 11 | `punch_in`, `d = ts.date()` | The attendance date is the **server-local** date, not the IST date (R1); overnight shifts ignored. | The 01:00 IST punch above gets `date: "2026-07-06"` instead of `2026-07-07`. Overnight 22:00 shift punching in at 01:00 lands on the wrong day. | `attendance_date()` implements R1 in IST including the overnight exception. |
| 12 | `punch_in` check-then-insert | Race: `find_one` then `insert_one`, no unique index. | 8 simultaneous identical punch-ins returned **eight 201s and stored 8 documents**. | Unique index `(emp_code, date)`; insert directly and map `DuplicateKeyError` to 409. |
| 13 | `punch_in` / `list_attendance` responses | Leak `_id` as `id`, return raw datetimes (ISO, no zone) instead of epoch ms. Contract: `_id` never appears; instants are ms. | `"id": "6acb..."` in every response; `"punch_in": "2026-07-06T19:30:00"`. | `to_record()` serialises explicitly: no `_id`, instants as ms, defaults for legacy fields (`half_day`, `history`). |
| 14 | `list_attendance` | Loads **every** matching document into memory, sorts and slices in Python; `total = len(docs)`. No indexes, so a full collection scan per request. | Fine on 9 documents, seconds and large memory on 100k. | `find().sort().skip().limit()` and `count_documents`, backed by indexes created at startup. |
| 15 | `list_attendance` params | Sort is by `date` only (no `emp_code` tie-break, so pages are unstable). `page=0` slices `[-20:0]` (empty page, nonzero total). Dates and `status` unchecked; `date_from > date_to` allowed. | `page=0` returns 200 with `total: 3` and no items. `date_from=garbage` and `status=BOGUS` both return 200. | Sort `(date desc, emp_code asc)`; validated page / page_size / dates / status; `date_from > date_to` is 422. |
| 16 | `/health` | Always returns ok, never talks to MongoDB. | Stop MongoDB: `/health` still says 200. | `ping` command; 503 on failure. |
| 17 | Startup | No indexes are created (only `_id_` exists); the starter has no uniqueness guarantee anywhere. | `index_information()` shows only `_id_`. | `ensure_indexes()` in the lifespan hook (idempotent), retried from `/health` if MongoDB was down at boot. |

**Looked at and decided it is fine**

- `load_dotenv()` does not override variables that are already set, so real environment variables win as required.
- Sync `def` endpoints with the synchronous PyMongo client: FastAPI runs them in a thread pool and `MongoClient` is thread-safe, so concurrency is fine. Switching to Motor would add complexity for no gain here.
- Hard-coded default URI `mongodb://localhost:27017` is only a fallback for local development; the environment variable takes priority.
- `status_code=201` on the two POST endpoints matches the contract.
